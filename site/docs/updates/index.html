Updates and recovery

One command updates everything, and it takes a snapshot first. Nothing installs on its own.

Update

subcult update

In order, it:

  1. Takes a snapshot, so you can boot back to this moment.

  2. Upgrades every package, then checks that kernel modules built for both kernels. If one did not, it says so and keeps the previous kernel bootable.

  3. Runs pending migrations.

  4. Updates firmware, AUR packages and mise tools.

  5. Offers to remove orphaned packages and old package files.

  6. Reports what changed, which services need a restart and whether to reboot.

Update commands
subcult update checkCount available updates without installing them
subcult update --dry-runShow what an update would do
subcult update migrate --pendingList migrations not yet run

A daily check counts available updates, and the bar's updates widget shows the number.

Channels

A channel decides where packages come from.

Update channels
ChannelPackages fromPick it when
stableA dated Arch Linux Archive snapshot, moved forward once Subarchy's tests install and boot itYou want a tested package set, the same on every machine. New installs start here.
edgeThe Arch mirrors, directlyYou want packages the day Arch ships them, and can live with the odd breakage
subcult channel set edge

subcult channel shows the current one.

Undo a bad update

  1. Reboot. The Limine boot menu lists one entry per snapper snapshot.

  2. Boot the snapshot taken just before the update. subcult update made it for you.

Factory reset

The installer keeps a read-only factory snapshot of the fresh system, outside the snapshot rotation. Factory reset, in the menu, swaps it in as the system on the next boot and starts first-boot setup again.

Factory reset modes
Keep my filesThe system goes back to new; your user and home folder stay
Remove everythingThe user and home folder go too, for handing the machine on

If the shell or lock screen crashes

The lock screen is a separate program from the shell. A shell crash cannot unlock the session.

If the shell crashes, it restarts by itself. Restart it yourself with systemctl --user restart subcult-shell.

If the lock screen crashes, the session stays locked: Hyprland shows a notice and a new lock screen starts within a second. If that keeps failing, switch to a text console with Ctrl + Alt + F3, sign in as the same user and run:

systemctl --user reset-failed subcult-lock.service
systemctl --user start subcult-lock.service

Then go back with Ctrl + Alt + F1 and type your password. journalctl --user -b -u subcult-lock.service says why it failed.
